📖 Lectura Fundamental 3 — Sección 2.1: Estimación del tamaño

¿Cómo se identifican los elementos de una pantalla?

La Lectura Fundamental 3 explica que para estimar el tamaño de un módulo, el punto de partida son los requerimientos: cada criterio de aceptación de la historia de usuario describe algo que el usuario debe poder hacer. Esa acción, traducida a pantalla, se convierte en uno o varios elementos HTML.

La regla práctica es leer cada criterio y preguntarse: ¿qué necesita el usuario ver o usar en la pantalla para cumplir esto? Por ejemplo:

Criterio → "El formulario debe tener campo de nombre completo" → 1 etiqueta (label) + 1 campo de texto (input) = 2 LOC
Criterio → "Debe existir un enlace a inicio de sesión" → 1 enlace (a href) = 1 LOC

Recuerden también contar los elementos estructurales que toda pantalla necesita aunque el requerimiento no los mencione explícitamente: la estructura base del archivo HTML, el contenedor principal y el formulario que envuelve los campos.

Paso a paso:

  1. Lean cada criterio de aceptación de la HU-01 (Paso 1) y tradúzcanlo en elementos HTML concretos usando la lógica de arriba.
  2. Sumen también los elementos estructurales: estructura base, contenedor y formulario.
  3. Para cada elemento, consulten el Recurso 1 y anoten las LOC que le corresponden.
  4. Sumen el total y obtengan el tamaño estimado del módulo.

📖 Lectura Fundamental 3 — Sección 2.1 · Lectura Fundamental 1 — Sección 2: Métricas e Indicadores

¿Qué es el rendimiento y cómo se usa para estimar el tiempo?

La Lectura Fundamental 1 define el rendimiento como la cantidad de líneas de código sin defectos que un programador produce en una hora, basado en un estándar de codificación. La fórmula es:

Rendimiento = LOC producidas ÷ Tiempo real de codificación (horas)

Idealmente, cada programador calcula su propio rendimiento midiendo sus proyectos anteriores. Como ustedes están en las primeras semanas del curso y aún no tienen esa historia personal, la Lectura Fundamental 3 propone partir de un inventario de referencia para construir esa base de datos propia.

Para este taller, usen como punto de partida un rendimiento de 10 LOC/hora, que representa a un estudiante que ya conoce la sintaxis básica de HTML pero aún está en proceso de práctica. Si el equipo considera que trabaja más lento (por ejemplo, porque es la primera vez que codifican en HTML), pueden usar 5 LOC/hora. Lo importante es que justifiquen por qué eligieron ese valor.

Con ese dato, la fórmula para estimar el tiempo es:

Tiempo estimado = LOC totales ÷ Rendimiento (LOC/hora)

Inventario de Elementos HTML
y su estimación en LOC

Use esta tabla como referencia para completar la estimación de tamaño del Paso 2 del taller. No modifiquen este recurso; solo consúltenlo.

¿Para qué sirve este inventario? Según la Lectura Fundamental 3, para estimar el tamaño de un proyecto de software necesitamos una referencia de cuántas líneas de código (LOC) requiere cada tipo de elemento. Este inventario es esa referencia. Recuerden: los comentarios, las llaves { } y las líneas en blanco no cuentan como LOC.
# Elemento HTML LOC por unidad Regla de cálculo Ejemplo de código
01 Estructura base (plantilla HTML) 5 LOC DOCTYPE + apertura/cierre de <html>, <head>, <body> <!DOCTYPE html><html>...</html>
02 Contenedor (div / section / article) 2 LOC 1 línea de apertura + 1 de cierre <div> … </div>
03 Formulario 2 LOC 1 línea de apertura + 1 de cierre <form> … </form>
04 Etiqueta (label) 1 LOC 1 por etiqueta, en una sola línea <label>Nombre:</label>
05 Campo de texto (input) 1 LOC 1 por campo, sin estilos <input type="text">
06 Botón (button / input submit) 1 LOC 1 por botón, sin estilos <button>Enviar</button>
07 Enlace (hipervínculo) 1 LOC 1 por enlace <a href="#">Ir</a>
08 Imagen 1 LOC 1 por imagen (etiqueta auto-cerrada) <img src="…" alt="…">
09 Párrafo / Encabezado 1 LOC 1 por elemento <p> o <h1>–<h6> <h2>Registro</h2>
10 Lista (ul / ol) N + 2 LOC Apertura + cierre de la lista (2 LOC) + 1 LOC por cada ítem <li> <ul><li>…</li></ul>
11 Tabla filas × cols × 2 Cada celda <td> o <th> ocupa apertura + cierre. Cuenten encabezados como una fila más. <table><tr><td>…</td></tr></table>
12 Lista desplegable (select) N + 2 LOC Apertura + cierre del <select> + 1 LOC por cada <option> <select><option>…</option></select>
Recuerden de la Lectura Fundamental 3: el inventario es una referencia, no una verdad absoluta. El número exacto de líneas puede variar según el estándar de codificación del equipo. Lo importante es ser consistentes con la misma referencia durante toda la estimación. También recuerden revisar la diferencia entre estimación y predicción antes de presentar su resultado.
